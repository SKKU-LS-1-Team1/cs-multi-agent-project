# CSA-81 하이브리드 검색 검증 (2026-11-09)

## 적용 결정

`HYBRID_ENABLED=true`, `HYBRID_WEIGHT=0.0`을 기본으로 사용한다.
키워드 검색으로 찾은 문서를 후보에 추가하되, 키워드 점수를 더하지 않고 기존 벡터 점수,
유형별 규칙 및 AI reranker로 정렬한다. `0.0`은 후보 추가가 켜진 상태이며,
완전히 이전 방식으로 돌아가려면 `HYBRID_ENABLED=false`를 지정한다.

원래 PR의 가중치 0.3은 펌웨어 문의에서 기존 reranker 대비 42/53 → 36/53으로 하락했다.
가중치 0.1과 0.2에서도 37/53이어서, 후보만 합치는 방식을 별도로 비교했다.
이 방식은 42/53을 유지하면서 전체 검색률이 가장 높았다. 유형별 예외 규칙은 추가하지 않았다.

## 평가 조건

- 최신 main `95a71fe`와 PR #121 `71ab183`을 병합한 코드에서 검증했다.
- 제공된 교육용 `synthetic_v1` valid 603건 중 정답 근거가 있는 589건을 사용했다.
  `data/raw/README.html`에 합성 데이터임이 명시되어 있고 원본 학습 파일과 해시가 동일하다.
- 로컬 PostgreSQL 문서 813개 전부 현재 청킹 입력의 해시와 일치했다.
- 임베딩: Gemini `gemini-embedding-2`, 1536차원. 판단: `jev-latest`의 실제 응답은
  `jev-1.14.0`, 보조 판단은 `gemini-3.8-flash`. reranker 가중치는 기존 기본값 0.5다.
- 문의 제목·본문으로 검색하고 정답 유형·제품·에러코드로 근거를 확정했다.
  정답 문서와 절이 최종 docs top-3 안에 있으면 성공으로 집계한다.
- 같은 문의 임베딩과 동일한 문의·절의 실제 모델 판단을 비교군에서 재사용했다.
  그 응답을 저장소의 `measure_hybrid()`에 다시 적용해 결과가 일치함을 확인했다.
- DB는 문서 조회만 수행했다. 기존 문의 및 시연 상태는 변경하지 않았다.

## 결과

| 검색 방식 | reranker 없음 | reranker 포함 |
|---|---:|---:|
| 기존 벡터 검색 | 435/589 (73.9%) | 463/589 (78.6%) |
| 키워드 후보 추가, 가산 0.0 **선택** | 469/589 (79.6%) | **500/589 (84.9%)** |
| 키워드 후보 추가, 가산 0.1 | 462/589 (78.4%) | 496/589 (84.2%) |
| 키워드 후보 추가, 가산 0.2 | 464/589 (78.8%) | 495/589 (84.0%) |
| 키워드 후보 추가, 가산 0.3 | 465/589 (78.9%) | 493/589 (83.7%) |

선택한 방식은 기존 reranker 대비 **37건 개선, 기존 정답의 오답 전환 0건**이었다.
각 비교군의 판단 실패는 0건이었다. 이 결과는 이번 표본에 대한 관측이다.

| 유형 | 건수 | 기존 reranker | 후보 추가 + reranker |
|---|---:|---:|---:|
| 설치 | 68 | 25 | 26 |
| 사양 | 90 | 90 | 90 |
| 견적 | 45 | 13 | 31 |
| 인증·규격 | 53 | 53 | 53 |
| 문서 요청 | 46 | 40 | 41 |
| 반품 | 53 | 34 | 45 |
| 주문·납기 | 53 | 49 | 49 |
| 고장 | 83 | 79 | 80 |
| 펌웨어 | 53 | 42 | 42 |
| 보증 | 45 | 38 | 43 |

본문 언어별 정답 건수도 감소하지 않았다. 세부 수치, 데이터 해시, 개선 티켓 ID 및
가중치 비교는 [JSON 결과](hybrid_retrieval_valid.json)에 있다.

쿼리 임베딩을 재사용한 로컬 비교에서 키워드 검색과 추가 SQL의 평균 시간은 4.2ms,
p95는 5.8ms였다. 전체 문의 처리시간(K1), 실제 분류·추출을 포함한 정확도,
서버 부하 상황의 지연은 이번 수치에 포함되지 않는다. test 분할은 사용하지 않았다.
합성 valid에서 선택한 설정이므로 실제 고객 문의의 성능을 보장하는 결과는 아니다.

## 실패 처리 및 호환성

- 키워드 검색이나 추가 SQL 실패 시 이미 성공한 벡터 결과를 그대로 반환한다.
  같은 벡터 검색을 다시 호출하지 않는다.
- 챗봇의 직접 `docs.search` 점수와 전환 기준, 사례 패턴 DB 및 지식 그래프 경로는 유지한다.
- 추가 후보도 기존 제품 필터 및 에러코드 우선 처리를 거친다.
- 신규 마이그레이션이나 문서 재임베딩은 필요 없다.
- 서버 `.env`에 `HYBRID_ENABLED=false` 또는 예전 가중치가 명시되어 있으면 기본값보다 우선하므로
  적용 시 `HYBRID_ENABLED=true`, `HYBRID_WEIGHT=0.0`을 확인한다.

```bash
uv run --all-extras python -m cs_agent.agents.retrieval --split valid --hybrid
uv run --all-extras python -m cs_agent.agents.retrieval --split valid --hybrid --rerank
```

후보 추가/점수 가산 구분, 장애 시 복구, 제품 필터, 원래 벡터 점수 보존,
실제 PostgreSQL의 절 조회 및 NULL 절 처리, 비교군의 판단 재사용을 회귀테스트로 확인한다.
